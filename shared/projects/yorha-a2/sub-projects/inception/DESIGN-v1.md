# Inception 架构设计 v1

> **一句话**:inception 不是"N 个 AI 角色凑一起聊天",而是——**一条唯一真相的世界事件流 + 每个角色和玩家都只是它的一个受限投影 + 一个按世界观规则推演的裁判**。世界能自洽的根就在这:所有视角都派生自同一个源,不存在互相打架的"平行真相"。

## 四个部件

### ① 世界本体 = 只增不改的事件流(世界总账)
- "真正发生了什么"一条条 append 进去,是**唯一客观真相**;当前世界状态 = 把这条流从头回放得到的结果。(event sourcing;类比 git 提交历史 / 账本。)
- **fork 是天然的**:从流的任意节点岔出一条新流 = 一个平行世界(git branch)。直接实现"任意节点 fork + 很多平行世界"。

### ② 每个 NPC = 世界流的"投影",不是孤立小宇宙
- 甲的上下文 **≠** 甲自己攒的一本独立记忆(那会跟世界脱节、时间长了各说各话);甲的上下文 = **世界总账里"甲在场 / 被告知 / 能推断"的那些事件,过滤投影给他**。
- **隔离与流动统一**:隔离靠投影时的过滤器(丙不在场就投影不到),流动靠事件先进总账、再分发给该知道的人。
- 例(吵架):甲乙当众吵一架 = **一个**事件进总账 → 自动投影进甲、乙、在场玩家三方;没在场的丙投影里没有、天然不知道。四份视角**永远一致**,因为本就是同一条流的四个投影,不是四本各写各的账。

### ③ 玩家 = 世界里一个由人操控的特殊 agent
- 行动 = 往世界流写一个"意图";多玩家共在 = 多人往同一条流写;共建未来 = 这条流由大家一起往下续。

### ④ 推演器(世界的裁判)—— 最核心也最难
- 行动意图进来,"世界里到底发生了什么"由推演器裁定:拿**世界观里的规则**(物理 / 社会 / 因果)+ 当前世界状态 → 裁定结果 → 写回总账。
- **这是"世界观完整推演"真正落地的地方**:世界观不是一段设定文本,是**喂给推演器的一套规则**。
- 多玩家同时动手 → 推演器像**数据库事务**一样把它们串成一个单一自洽的序列(世界一个 tick 一个 tick 地推),世界流永远是一条不打架的线。

## 与当前引擎的连续性(不是推倒重来)
- 现在引擎的 `RuntimeState`(每轮整个重写)+ Phase 1–3 记忆护栏,就是"世界状态 + 谁知道什么"的**雏形版**,只是挤在单人单会话里。
- inception = 把它**重构成 event-sourced 总账 + 多 agent 投影 + 独立推演器**——不是推倒重来,是给那个已经在搏斗的核心问题,换一副扛得住"多人 + 持久 + fork"的骨架。

## 命门(该最先做原型验证的)
1. **推演器**:让它按世界观规则、在多人乱入下,一次次裁出既守规则、又有涌现惊喜、还自洽的结果——比现在"生成一回合叙事"难**一个量级**的 LLM 推理问题。
2. **成本 / 性能**:每个 NPC 一个投影 + 持久 + fork;投影**不能每次重放整条流**(要增量 / 快照)。多玩家实时推演的 token / 算力是另一座山。

> ⚠️ "生成世界"反而是相对容易的部分;**自洽 + 成本才是命门**。先验证这两块,别先堆世界生成。
