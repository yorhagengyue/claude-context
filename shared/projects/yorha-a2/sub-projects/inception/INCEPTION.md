# Inception — 项目愿景与定位

> **一句话**:把任何一本书(已有的、或用户自己造的)的世界观,完整推演成一个**可进入的、多玩家共建的活世界**——纯文字形态,本质是上下文管理。

## 这是什么(想法)

**不是**"AI 互动故事引擎"(那是工具、是手段)。inception 是**一个你能走进去的世界**:

- 喂进一本书 / 一个设定,世界观**完整推演**开。
- 里面**每个 NPC 是独立 subagent、各有各的上下文**——"谁知道什么"天然被隔离。
- **多个玩家共在同一个持久世界**里,一起**共建未知的未来**(涌现,一切未定)。
- 世界**可 fork**:任意节点、有权限的用户能岔出一个**平行世界**。
- 世界的来源:玩家本身 / 预设内容 / 任何书。

**形态**:纯文字(3D / 游戏画面**不考虑**)。核心竞争力在**上下文管理**,不在画面。

## 位置(在整个盘子里的定位)

- **inception = 最终目标 / 北极星**(2026-07-08 Gengyue 拍板:项目**彻底转向**此名 + 此愿景)。
- **当前的 `ai-interactive-story` 引擎 = 通往 inception 的中间站、是手段不是目的**。现在做的(单人 + 一段对话的故事生成)只是一站;**远没到"做完"**。
- **难度量级往上是必然且被接受**:多玩家共在 + 持久 + fork = "世界服务器"级,不是聊天产品体量。
- **版权 / 法律**(吃已有版权书的 IP 问题):**后议,当前不考虑**。
- **分工**:inception 的**底层只有 Gengyue 本人做**;当前产品(ai-story)团队继续推;**未来若真出现分歧再把项目拆两份,当下不拆**。
- ⚠️ "当前这一站跟 inception 什么关系(边跑边埋地基 vs 平行另起、底层现在开工还是等当前告一段落)":**用户暂时搁置,后续再定**。

## 核心创新点

1. **NPC = 独立 subagent 的上下文** → 用架构隔离解决"AI 说出不该知道的事",而非 prompt 求它别剧透。(当前引擎 Phase 3 knower 轴 / 发言者门 = 它的上一代雏形。)
2. **世界 = 可 fork 的持久事件树** → "平行世界"从口号变成 git 式的具体机制,顺手解决"既想多人共建主线、又想探索别的可能"。
3. **多玩家共建 + 涌现** → 世界的未来由多人一起续、全未知。

## 真正的深水区(最该早想的)

**独立上下文解决的是"隔离",而世界要活靠的是"信息流动 + 共识"——两者是反的。** N 个独立 subagent + 多个自由玩家 + 持久 + fork,"**这还是同一个自洽世界吗**"是最烧脑的问题。当前引擎 Phase 1–3 记忆护栏是在**单人单会话**里搏斗这个;放到多 agent 多玩家持久世界是**指数级**难度,不是加法。

→ inception 真正的核心技术**不是"生成世界",而是"让世界在无数独立视角 + 多人乱入 + 不断 fork 之后还保持自洽"**。设计见 [DESIGN-v1.md](DESIGN-v1.md)。
