## 系统定义

StudyOS 是耿越给时浩然做的**个人学习系统**，只服务一个人，不做多用户。两部分：

**Agent 端** —— Claude Code / Codex 直接在仓库里工作，读根 `CLAUDE.md` 的规则，帮时浩然理解课程、分析错题、扩展系统，并把过程写进 `docs/DEV-LOG.md`。`AGENTS.md` 只是指针，规则单一真源是根 `CLAUDE.md`。

**网页端** —— 本机 `python tools/app.py` 起服务，只听 `127.0.0.1:8765`。左边课程—模块—资料树，右边读正文和文件，顶部「刷新全部课程」；服务开着每 15 分钟自动刷一次。**网页端不含 AI 对话**，也不会唤起外部 Agent。

覆盖的资料范围 = 课件文件、课程页面、老师公告、作业说明。四门课：ACCT2011 / ACCT2019 / IBUS2020 / IBUS2105（悉尼大学 2026 S2）。

## 边界与红线（这个项目最重要的部分）

**身份边界**：学习者是时浩然，不是耿越。仓库里反复写明「不要把学习者与项目制作人混为一人」。record 仓 DRAWER.md 的候选事实 `c-9f1e3002` 正是这条——**study-os 的四门课不得当成耿越本人的学籍或课程**（must_confirm、open）。

**Canvas 只读**：只发 GET，不提交、不答题、不签到、不读成绩和提交记录。文档同时提醒：token 本身的权限由学校决定，**不能当成天然只读凭证**。

**凭证**：只放项目根被 git 忽略的 `.env`，不进代码、文档、日志、聊天、PR。`tools/save.py` 在提交前扫描 token 形态字符串，命中就拒绝提交。下载文件只进被忽略的 `state/`。

**`student/` 同步永不改写** —— 那是人写的学习记录（journal / stuck / ideas / ai-log / group 五类模板）。`raw/`、`content/` 是早期快照，不得冒充最新资料。

**合并权**：时浩然的改动一律走功能分支 + PR，**只有耿越审核通过才能合并**。技术检查通过、时浩然同意、Agent 自评都不能替代。Agent 不擅自合并、不直推 main。

**不代做考核**：可以拆题、举例、分析、辅导，不代写要交的作业或考试；课程要求用 Cogniti 的地方照课程做。

## 技术栈与代码地图

纯 Python 标准库 + 原生 HTML/JS，**零第三方依赖**（决策原文：降低上手门槛）。Python 3.9+。

| 文件 | 职责 |
|---|---|
| `tools/app.py` | 本机 HTTP 服务、资料浏览接口、自动刷新调度 |
| `tools/canvas.py` | Canvas 只读客户端：同源 GET、公网地址校验、逐跳重定向检查、下载跨域不带 token |
| `tools/material_sync.py` | 同步主力：翻页、模块/正文递归发现、下载、校验、原子替换、失败保留 |
| `tools/library.py` | 旧快照适配 + 正文净化（不执行教师页面脚本） |
| `tools/sync.py` | 旧命令入口 + 悉尼时区（含夏令时）换算 + 生成 `content/overview.md` 和 CHANGELOG |
| `tools/save.py` | 手动 Git 保存（带 token 扫描）；App 和同步**不**调用它 |
| `web/` | 三件套前端 |
| `docs/` | IDEA（耿越最初的分层构想）/ DECISIONS / DEV-LOG / VALIDATION / COURSES / CANVAS-API |

<details><summary>历史：PR #2「修复 Mac 首次同步时附件连接长时间等待」（2026-09-10 提，2026-09-18 合并）</summary>

问题：时浩然第一次在 Mac 上同步时附件下载极慢。附件存储域名解析出 8 个地址、只有 1 个能在 3 秒内连上，而原实现对每个地址**串行等最多 45 秒**，已保存附件之间出现约 47.6 秒间隔。

改法：单个地址的 TCP/TLS 建连预算压到 **5 秒**，握手成功后恢复 45 秒读超时；优先重试同一主机上次成功的地址，但**每次仍重新校验 DNS**，旧地址只有仍在有效公共地址列表里才复用。只动 `tools/canvas.py`，加 6 条回归测试。

合并前复核（Claude 按 owner 指示执行，独立重跑而非照抄 DEV-LOG）：PR 分支 50/50 过、main 基线 44/44 过；**把 main 的 `canvas.py` 换回去跑那 6 条新测试会全部报错**，证明测试钉的是新行为不是空测试；合并后的 main 再跑一遍仍 50/50。安全不变式（每次重新解析 DNS + 拒内网 + 缓存地址须仍在校验过的列表里）与证书校验路径均未被破坏；45 秒读超时在握手后还原，大附件下载不受影响。

**留下的两点，都不是 bug**：① 5 秒是 TCP+TLS **共用**预算，整条链路都慢的网络（酒店 Wi-Fi、手机热点）可能从「慢但成功」变成「8 个地址各 5 秒后整体失败」——失败保留旧文件，真撞到再把 5 秒提到 8–10 秒即可；② `socket._GLOBAL_DEFAULT_TIMEOUT` 是 CPython 私有名，本仓实际永远走 `timeout=45` 分支，纯防御代码，但若 Python 动了这个常量，炸的是全部网络请求。

## 已知的 Canvas 坑（`docs/CANVAS-API.md`，跨项目可复用）

- 文件列表 403、页面列表 404 = 权限问题，**不等于该课没资料**；按 id 单取往往能拿到。
- 四门课的 `syllabus_body` **全是空的**，真正的课程说明在页面、附件和学校官网大纲里。
- **0 分不等于可选**：ACCT2011 的 Draft Part A 门户 points 是 0，但指南写明必交。
- **作业标题不等于交付物**：IBUS2105 的 "Feasibility Report" 实际要交两份文件（Cogniti 生成的 PDF + 自己写的 2000 字反思 Word）。
- 权重看 `assignment_groups.group_weight`，不看单题 points（ACCT2011 有个权重 100 的 "Adjustment" 组，它不是考核）。
- 公告接口**默认只查近 14 天**，必须显式传 `start_date`。
- Canvas 时间是 UTC；悉尼 2026-10-04 进入 AEDT（+11）。
- 两门会计课的 tutorial 练的是**上一周** lecture 的内容。
- Canvas 和学校官网大纲有已知的不一致（ACCT2019 期中时长、IBUS2020 小组权重、ACCT2019 的 LO4/5）——系统的原则是**并列呈现、不替用户挑一个**。
